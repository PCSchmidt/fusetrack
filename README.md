# FuseTrack

Multi-sensor fusion tracking for counter-UAS, in Rust: a scenario simulator, filters, and (planned) a head-to-head benchmark of classical vs. learned data association.

**Status: v0.1, in progress.** A single-target EKF with a radar simulator is working and statistically validated. Multi-target tracking, IMM, additional sensors and the learned-association comparison are not built yet; see the [roadmap](docs/roadmap.md).

Part of [physical-ai-portfolio](https://github.com/PCSchmidt/physical-ai-portfolio).

## Problem

Fielded counter-UAS systems fuse noisy, asynchronous reports from radar, EO/IR and RF sensors into one track picture. The hard parts are nonlinear measurements, manoeuvring targets, clutter, and deciding which measurement belongs to which target. This project builds that stack from first principles and measures it honestly.

## What works today

- **Simulator** (`sim`): a target driven by piecewise-constant random acceleration, seeded for reproducibility.
- **Radar model** (`models`): 2D range-bearing sensor with Gaussian noise and angle wrapping.
- **EKF** (`ekf`): constant-velocity model, nonlinear range-bearing update, Joseph-form covariance update, bearing innovation wrapped across the ±π branch cut.

## Results

Monte Carlo over 100 seeded runs of 100 steps each (first 10 steps discarded), with data generated by the filter's own motion model. Radar: σ_range = 15 m, σ_bearing = 0.003 rad; target acceleration σ = 2 m/s².

| Metric | Measured | Ideal |
| --- | --- | --- |
| Mean NEES (state error vs. filter covariance) | 3.89 | 4 (state dimension) |
| Mean NIS (innovation vs. predicted covariance) | 1.97 | 2 (measurement dimension) |
| Position RMSE, filtered | 14.2 m | |
| Position RMSE, raw radar fixes | 23.2 m | |

NEES and NIS near their ideal values mean the filter's reported uncertainty matches its actual error. These are consistency checks against matched-model simulated data, not claims about real radar performance. Reproduce with `cargo test --test ekf_consistency -- --nocapture`.

## Limitations

- One target, one sensor, one motion model. No clutter, missed detections or association yet.
- Simulated data generated from the filter's own model, which is the easy case. Manoeuvre mismatch is the next thing to test.
- No real sensor data.

## Run

```
cargo test
cargo run --release --example single_target
```

Requires a stable Rust toolchain. CI runs `fmt`, `clippy -D warnings` and the tests.

## Planned

IMM for manoeuvring targets, GNN and JPDA association, clutter and missed-detection simulation, EO bearing-only and RF sensors, OSPA/GOSPA evaluation, out-of-sequence measurement handling, a learned association model benchmarked against classical baselines, and Cursor-on-Target output.

## Scope

Simulation only. Defensive sensing and tracking; no weapons or targeting functionality. Public methods and synthetic data only.
